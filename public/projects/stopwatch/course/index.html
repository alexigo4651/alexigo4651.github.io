2Что происходит в железе

Arduino и пины

Arduino Uno — маленький компьютер с ножками-выводами, которые называют пинами. У каждого пина есть номер: цифровые D0–D13 и аналоговые A0–A5. Аналоговые тоже умеют работать как обычные цифровые, в программе у них номера 14–19 (A0 = 14, A1 = 15 и так далее).

Пин может работать в двух ролях:

  • Выход (OUTPUT). Программа сама выставляет на нём напряжение: HIGH = 5 вольт (логическая 1) или LOW = 0 вольт (логический 0).
  • Вход (INPUT). Программа «слушает», какое напряжение на пине снаружи, например нажата ли кнопка.

Пины D0 и D1 заняты связью с компьютером по USB, поэтому в твоих схемах их не трогают.

Семисегментный индикатор

Каждая цифра собрана из 7 светодиодных палочек-сегментов и точки. Их всегда называют буквами: a сверху, дальше по часовой b, c, d, e, f, в середине g, точка — dp (decimal point). Зажигая разные сегменты, получаем разные цифры: для «1» горят только b и c.

У тебя индикатор на 4 разряда (4 цифры, 12 выводов). Выводов мало, потому что сегменты одинаковых букв всех четырёх цифр соединены между собой внутри: один вывод «a» на все четыре цифры. Плюс у каждой цифры есть свой общий вывод.

Общий анод: почему всё «наоборот»

Светодиод светится, когда ток идёт от плюса (анод) к минусу (катод). В индикаторе с общим анодом плюсовые концы всех сегментов одной цифры соединены в один вывод разряда. Отсюда правило, которое надо запомнить:

Что делаемВывод разряда (цифры)Вывод сегмента
ВключитьHIGH (подаём плюс)LOW (даём путь к минусу)
ВыключитьLOWHIGH

Сегмент горит, только если его цифра включена (HIGH) и сам сегмент притянут к нулю (LOW). Поэтому в коде ты увидишь «перевёрнутые» записи: LOW значит «зажечь сегмент».

Мультиплексирование: обман глаза

Выводы сегментов общие для всех цифр. Если включить все четыре разряда сразу, на всех будет одна и та же цифра. Поэтому программа зажигает цифры по очереди: первую на 4 миллисекунды, потом вторую, третью, четвёртую, и снова по кругу. Полный круг занимает 16 мс, то есть около 60 раз в секунду. Глаз не успевает заметить мигание и видит все четыре цифры одновременно. Ниже в живой модели можно замедлить этот процесс и увидеть его своими глазами.

Кнопка и подтяжка

Кнопка подключена между пином D9 и землёй (GND). Внутри Arduino есть резистор, который можно подключить от пина к +5 В: режим INPUT_PULLUP («вход с подтяжкой вверх»). Получается так:

  • кнопка отпущена — резистор тянет пин к 5 В, читаем HIGH (1);
  • кнопка нажата — пин замкнут на землю, читаем LOW (0).

Опять «наоборот»: нажатие = 0. Без подтяжки пин «висел бы в воздухе» и выдавал случайные значения.

Дребезг. Металлические контакты кнопки в момент нажатия несколько миллисекунд хаотично замыкаются и размыкаются. Программа может принять одно нажатие за пять. Лечится паузой: заметили изменение, подождали 20–30 мс, пока контакты успокоятся.

Резисторы на сегментах

Светодиоду нельзя давать столько тока, сколько он «захочет», он сгорит или сожжёт пин. Резистор на каждом сегменте ограничивает ток. На выводы разрядов резисторы не ставят, иначе яркость зависела бы от числа горящих сегментов.

Внимание к варианту 2. Там указаны резисторы 240–360 Ом. Через один вывод разряда идёт ток всех горящих сегментов сразу; при 8 сегментах и таких резисторах это может превысить допустимые для пина Arduino 40 мА. Безопаснее поставить 680 Ом – 1 кОм, как в варианте 1, или включать разряды через транзисторы.

4Как цифра становится числом

В коде есть загадочная строчка F[] = {63, 6, 91, 79, ...}. Это «шрифт» — для каждой цифры от 0 до 9 записано, какие сегменты зажечь. Каждый сегмент — это один бит (ноль или единица) в числе:

Бит0123456
Сегментabcdefg
«Вес»1248163264

Код цифры — сумма весов горящих сегментов. Для «0» горят a, b, c, d, e, f: 1 + 2 + 4 + 8 + 16 + 32 = 63. Для «1» горят b и c: 2 + 4 = 6. Вариант 3 пишет те же числа в шестнадцатеричном виде: 0x3F = 63, 0x06 = 6. Это одни и те же числа, просто разная запись.

Пощёлкай по сегментам или нажми цифру внизу — увидишь её код:

Десятичный код: 0
Шестнадцатеричный: 0x00

6Словарь: все слова из кода

Программа для Arduino пишется на языке C++. Ниже каждое слово и значок, которые встречаются в трёх вариантах.

Знаки препинания

ЗнакЧто значит
//Комментарий. Всё после него до конца строки компьютер игнорирует.
;Конец команды, как точка в предложении. Забытая ; — самая частая ошибка новичка.

Типы данных: что лежит в «коробке»

Переменная — это подписанная коробка в памяти, куда кладут число. Тип говорит, какого размера коробка.

СловоЧто хранит

Переменные, объявленные вне функций (в начале файла), называются глобальными. Они живут всё время работы программы, и в начале в них лежит 0, если не указано другое.

7Вариант 3 построчно

Начинаем с самого понятного. Слева код, справа объяснение.

Таблицы и переменные

const uint8_t S[8] = {6, 7, 8, A0, A1, A2, A3, A4};    // a b c d e f g dp

Массив S (от «segments») из 8 элементов: номера пинов, к которым подключены сегменты, по порядку a, b, c, d, e, f, g, dp. S[0] = 6 — сегмент a на D6. S[7] = A4 — точка.

const uint8_t D[4] = {5, 4, 3, 2};

Массив D (от «digits»): пины разрядов слева направо. Разряд 1 на D5, разряд 4 на D2.

const uint8_t F[10] = {0x3F, 0x06, 0x5B, 0x4F, 0x66,
                       0x6D, 0x7D, 0x07, 0x7F, 0x6F};

«Шрифт» F (от «font»): коды цифр 0…9 из раздела 4. F[7] = 0x07 — код семёрки.

uint8_t d, m, b = 1;

Три переменные сразу.
d — какой разряд горит сейчас (0…3).
m — режим: 0 = сброшен, 1 = идёт счёт, 2 = остановлен.
b — каким кнопка была в прошлый раз. Начинаем с 1, потому что отпущенная кнопка читается как 1.

uint16_t n;

n — сколько секунд насчитали.

uint32_t t;

t — отметка времени (в мс), когда началась текущая секунда.

setup — настройка

void setup() {

Начало функции настройки, выполнится один раз.

  for (uint8_t i = 0; i < 8; i++) pinMode(S[i], OUTPUT);

Повторить 8 раз: сделать выходом пин S[i]. По сути это 8 строк pinMode(6, OUTPUT); pinMode(7, OUTPUT); …, записанные одной.

  for (uint8_t i = 0; i < 4; i++) pinMode(D[i], OUTPUT);

То же для четырёх пинов разрядов.

  pinMode(9, INPUT_PULLUP);
}

Пин кнопки — вход с подтяжкой. Закрывающая скобка завершает setup.

loop, часть 1 — кнопка

void loop() {
  uint8_t c = digitalRead(9);

Читаем кнопку прямо сейчас и кладём в новую переменную c (current — текущее). 1 = отпущена, 0 = нажата.

  if (c != b) {

Если сейчас не так, как было в прошлый раз, значит кнопку только что нажали или отпустили. Пока кнопку держат, c и b равны, и повторно ничего не срабатывает.

    b = c; delay(20);

Запоминаем новое состояние и ждём 20 мс, пока пройдёт дребезг.

    if (!c) {

!c верно, когда c = 0, то есть кнопку именно нажали. Отпускание игнорируем.

      m = (m + 1) % 3;

Следующий режим по кругу: 0 → 1 → 2 → 0. Остаток от деления на 3 не даёт выйти за 2: (2 + 1) % 3 = 0.

      if (m == 1) t = millis();

Перешли в «счёт» — запоминаем момент старта.

      if (!m) n = 0;
    }
  }

!m верно, когда m = 0. Перешли в «сброс» — обнуляем секунды. Две скобки закрывают оба if.

loop, часть 2 — счёт времени

  if (m == 1 && millis() - t >= 1000) {

Если идёт счёт и с отметки прошло 1000 мс или больше — наступила новая секунда. millis() - t — сколько прошло.

    t += 1000;

Сдвигаем отметку ровно на секунду вперёд. Не t = millis(), чтобы мелкие задержки не накапливались и секундомер не отставал.

    if (++n >= 60) m = 2;
  }

Прибавляем секунду. Дошли до 60 — переходим в режим «стоп», счёт замирает на 60.

loop, часть 3 — вывод на индикатор

  digitalWrite(D[d], LOW);

Гасим разряд, который горел. Если этого не сделать, при смене сегментов на нём мелькнёт чужая цифра.

  d = (d + 1) & 3;

Переходим к следующему разряду: 0 → 1 → 2 → 3 → 0. & 3 работает как % 4: 4 & 3 = 0.

  uint8_t k = F[d == 0 ? n / 1000
            : d == 1 ? n / 100 % 10
            : d == 2 ? n / 10 % 10
            :          n % 10];

Выбираем, какую цифру числа n показать в этом разряде, и берём её код из шрифта. Цепочка «?:» читается так: если d = 0 — тысячи, иначе если d = 1 — сотни, иначе если 2 — десятки, иначе — единицы.
Пример, n = 45: 45 / 1000 = 0; 45 / 100 % 10 = 0; 45 / 10 % 10 = 4; 45 % 10 = 5. На экране «0045».

  for (uint8_t s = 0; s < 7; s++)
    digitalWrite(S[s], (k >> s & 1) ? LOW : HIGH);

Для каждого из 7 сегментов: если его бит в коде равен 1 — пишем LOW (зажечь, ведь общий анод), иначе HIGH (погасить).

  digitalWrite(S[7], (m == 1 && millis() - t < 500) ? LOW : HIGH);

Точка: горит, если идёт счёт и мы в первой половине секунды. Получается мигание раз в секунду — видно, что секундомер работает. Точка мигает на всех четырёх разрядах.

  digitalWrite(D[d], HIGH);

Сегменты выставлены — включаем новый разряд. Загорается нужная цифра.

  delay(4);
}

Даём цифре посветить 4 мс. Потом loop начинается заново со следующим разрядом.

8Вариант 1: та же программа, сжатая

Вариант 1 работает на той же схеме и делает то же самое, но экономит каждый символ. Ниже каждая хитрая строка и её «развёрнутый» вид.

byte m,l=1,c,s;unsigned long t;

Те же переменные под другими именами: l (last) = b из варианта 3, c = номер разряда (d), s = секунды (n).

for(byte p=2;p<19;p++)
  if(p<9||p>13)pinMode(p,OUTPUT);

Перебираем пины 2…18 и делаем выходом те, что меньше 9 или больше 13. Получается D2–D8 и 14–18 (это A0–A4). Пины 9–13 пропускаем: на 9 кнопка, 10–13 не используются. Без массивов, но зато привязано к конкретной распиновке.

bool b=digitalRead(9);
if(b!=l&&(l=b,delay(30),!b)){

Самая хитрая строка. Оператор запятая выполняет выражения слева направо и отдаёт результат последнего. Значит, (l=b, delay(30), !b) = «запомни состояние, подожди 30 мс, ответь: нажата ли кнопка?». А && выполняет правую часть, только если левая верна. Развёрнуто:

if (b != l) {
  l = b; delay(30);
  if (!b) { ... }
}
if(++m>2)m=0;
if(m<2)s=0;
t=millis();

Сначала увеличиваем m; если стало 3 — обратно в 0. Затем при режимах 0 и 1 обнуляем секунды (при старте и при сбросе). Отметку времени ставим при любом нажатии — на результат это не влияет.

if(m==1&&millis()-t>=1000){t+=1000;if(++s>59)m=2;}

Ровно как в варианте 3: s > 59 — то же, что s >= 60.

digitalWrite(5-c,0);c=(c+1)&3;

Вместо массива D — формула. При c = 0 получается пин 5 (разряд 1), c = 1 → 4, c = 2 → 3, c = 3 → 2. Работает только потому, что разряды подключены к идущим подряд пинам. 0 — это LOW.

byte k=F[c<2?0:c<3?s/10:s%10];

Число не больше 60, поэтому первые два разряда всегда показывают 0. Третий (c = 2) — десятки, четвёртый — единицы.

for(byte i=0;i<7;i++)
  digitalWrite(S[i],!(k>>i&1));

Бит 1 → !1 = 0 = LOW → сегмент горит. Бит 0 → !0 = 1 = HIGH → не горит. То же самое, что «? LOW : HIGH».

digitalWrite(S[7],!(m==1&&millis()-t<500));
digitalWrite(5-c,1);delay(4);

Мигающая точка, включение разряда, пауза 4 мс. Всё как в варианте 3.

Вывод: короткий код не быстрее и не лучше. Компилятор превращает оба варианта почти в одно и то же. Пиши как в варианте 3: через полгода ты сам скажешь себе спасибо.

9Вариант 2: что отличается

Логика полностью совпадает с вариантом 1. Отличается только распиновка (см. таблицу в разделе 3):

const byte S[]={2,3,4,5,6,7,8,A0}

Сегменты a…g на пинах D2–D8 подряд, точка на A0.

for(byte p=2;p<15;p++)if(p!=9)pinMode(p,OUTPUT);

Выходами становятся пины 2…14 кроме 9 (кнопки). 14 — это A0.

digitalWrite(13-c,0); ... digitalWrite(13-c,1);

Разряды на D13, D12, D11, D10: c = 0 → пин 13 (разряд 1) … c = 3 → пин 10 (разряд 4).

На D13 на плате Uno распаян встроенный светодиод «L». Он будет слегка светиться вместе с первым разрядом — это нормально.

11. Найди ошибки

отладка

В этом куске 4 ошибки. Одна не даст программе загрузиться, три остальные загрузятся, но схема будет работать неправильно. Найди все.

const uint8_t S[8] = {6, 7, 8, A0, A1, A2, A3, A4}
const uint8_t D[4] = {5, 4, 3, 2};

void setup() {
  for (uint8_t i = 0; i < 7; i++) pinMode(S[i], OUTPUT);
  for (uint8_t i = 0; i < 4; i++) pinMode(D[i], OUTPUT);
  pinMode(9, INPUT);
}
// ... в loop:
  for (uint8_t s = 0; s < 7; s++) digitalWrite(S[s], (k >> s & 1) ? HIGH : LOW);
Ответ
  1. Нет ; после первого массива — ошибка компиляции.
  2. i < 7 в первом цикле: пин точки S[7] не стал выходом, точка не будет работать. Нужно i < 8.
  3. INPUT вместо INPUT_PULLUP: пин кнопки «висит в воздухе», режимы будут переключаться сами.
  4. ? HIGH : LOW перепутано для общего анода: будут гореть все сегменты, кроме нужных.

12. Финал: две кнопки

с нуля

Добавь вторую кнопку на D10 (тоже к GND). Кнопка D9 — старт/пауза (можно продолжать после паузы), кнопка D10 — сброс в ноль. Напиши программу с нуля, подглядывая в вариант 3 только при необходимости.

Подсказка

Вместо режима m удобнее bool run. Для каждой кнопки своя переменная прошлого состояния. Блок вывода на индикатор не меняется вообще.

Ответ
const uint8_t S[8] = {6, 7, 8, A0, A1, A2, A3, A4};
const uint8_t D[4] = {5, 4, 3, 2};
const uint8_t F[10] = {0x3F, 0x06, 0x5B, 0x4F, 0x66, 0x6D, 0x7D, 0x07, 0x7F, 0x6F};

uint8_t d, b1 = 1, b2 = 1;   // разряд и прошлые состояния двух кнопок
bool run = false;            // идёт ли счёт
uint16_t n;
uint32_t t;

void setup() {
  for (uint8_t i = 0; i < 8; i++) pinMode(S[i], OUTPUT);
  for (uint8_t i = 0; i < 4; i++) pinMode(D[i], OUTPUT);
  pinMode(9, INPUT_PULLUP);
  pinMode(10, INPUT_PULLUP);
}

void loop() {
  uint8_t c = digitalRead(9);            // старт/пауза
  if (c != b1) {
    b1 = c; delay(20);
    if (!c && n < 60) { run = !run; if (run) t = millis(); }
  }
  c = digitalRead(10);                   // сброс
  if (c != b2) {
    b2 = c; delay(20);
    if (!c) { run = false; n = 0; }
  }
  if (run && millis() - t >= 1000) { t += 1000; if (++n >= 60) run = false; }

  digitalWrite(D[d], LOW);
  d = (d + 1) & 3;
  uint8_t k = F[d == 0 ? n / 1000 : d == 1 ? n / 100 % 10 : d == 2 ? n / 10 % 10 : n % 10];
  for (uint8_t s = 0; s < 7; s++) digitalWrite(S[s], (k >> s & 1) ? LOW : HIGH);
  digitalWrite(S[7], (run && millis() - t < 500) ? LOW : HIGH);
  digitalWrite(D[d], HIGH);
  delay(4);
}

Упрощение: после паузы неполная секунда начинается заново. Если хочешь точности, сохраняй остаток millis() - t в момент паузы и вычитай его при продолжении — это задание со звёздочкой.
